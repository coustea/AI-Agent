采用 **5 步讲解框架**展开每个概念：
1. **概念引入** — 简洁定义，"是什么"

### progressive（渐进式结构）

```markdown
# 进程调度策略

## 概述

进程调度是操作系统的核心功能之一。当多个进程竞争 CPU 时，调度器需要决定谁先执行、执行多久。理解调度策略，是理解操作系统如何管理并发的基础。

## 核心概念

### 先来先服务（FCFS）

**定义**：按进程到达就绪队列的顺序依次分配 CPU。

**类比**：像银行排队办业务——先到先办，不管你办多久。

**原理**：FCFS 是最简单的非抢占式调度。进程一旦获得 CPU 就一直运行到结束或阻塞，不会被打断。

**示例**：P1(到达0, 突发5) → P2(到达2, 突发3) → P3(到达4, 突发1)。P1 运行 0-5，P2 运行 5-8，P3 运行 8-9。平均等待时间 = (0+3+4)/3 = 2.33。

**误区**：FCFS 不一定是"最公平"的——长进程在前会拖慢所有后续进程（护航效应）。

### 短作业优先（SJF）

**定义**：优先选择预计运行时间最短的进程。

**类比**：超市快速通道——买得少的人先结账，提高整体吞吐。

**原理**：SJF 在理论上能最小化平均等待时间，但需要预知进程的运行时间，实际中难以实现。

**误区**：SJF 可能导致长进程饥饿——如果短进程不断到达，长进程可能永远得不到 CPU。

## 应用场景

- 批处理系统常用 FCFS；交互系统需要更快的响应时间，倾向 RR
- 实时系统需要可预测的调度延迟，使用优先级调度

## 总结

- FCFS 简单但有护航效应
- SJF 理论最优但可能饥饿
- RR 公平但上下文切换开销大
```

### exam_points（考点式结构）

```markdown
# 进程调度策略 - 考点精讲

## 高频考点 TOP 3

### 考点1：RR 时间片大小的影响

**考点解读**：考查时间片大小对系统性能的双重影响

**答题线索**：时间片过大→退化为 FCFS；时间片过小→切换开销占比过大。通常取 10-100ms。

**易错陷阱**：误以为时间片越小响应越快——忽略了上下文切换的时间开销。

### 考点2：SJF 的饥饿问题

**考点解读**：考查 SJF 的固有问题和解决方案

**答题线索**：饥饿=长进程可能永远得不到 CPU。解决方案：老化（aging）—等待时间越长优先级越高。

## 复习策略

- 画 Gantt 图是必考技能，务必练熟
- 三种策略的对比表要能默写
```

### case_driven（案例驱动结构）

```markdown
# 进程调度策略

## 引入案例

三个进程 P1(0,5)、P2(2,3)、P3(4,1) 同时到达，如何安排执行顺序？

## 概念解析

**案例中的核心概念**：
- FCFS：按到达时间 P1→P2→P3，平均等待 2.33
- SJF：按突发时间 P3→P2→P1，平均等待 1.67（假设均可抢占）
- RR(time=2)：P1(2)→P2(2)→P3(1)→P1(2)→P2(1)→P1(1)

## 原理透视

同一组进程，不同策略产生截然不同的执行序列和等待时间。选择策略的本质是在公平性、吞吐量和响应时间之间做权衡。

## 变式案例

如果 P3 的突发时间改为 10 呢？FCFS 和 SJF 的差距会更大还是更小？

## 总结

调度策略的选择取决于系统目标——批处理重吞吐，交互系统重响应，实时系统重可预测性。
```

## 深度控制（depth_level）

- `quick`：每概念 5-10 行，侧重结论和关键类比，省略推导细节
- `standard`：每概念 15-30 行，含定义、类比、原理、示例、误区
- `deep`：每概念 30-60 行，含完整推导、边界情况、多角度验证

## 关注模式（focus_mode）

- `key_concepts`：聚焦 2-3 个核心概念，深入讲解
- `weak_points`：针对易错点、难点加强讲解，多给误区澄清
- `full_coverage`：覆盖 Worker Task 中所有大纲项，每项至少一节
