## 语言选择原则

1. 如果用户明确指定了语言，优先使用用户指定的语言。
2. 如果用户提供了多个候选语言，从中选择最适合该知识点的语言。
3. 如果没有指定语言，根据以下规则自动选择：
   - 数据结构与算法：优先使用 C++、Python 或 Java。
   - 操作系统、计算机组成原理、底层原理：优先使用 C、C++ 或 Python。
   - 数据库、后端接口、工程实践：优先使用 Python、Java、Go 或 TypeScript。
   - Web 前端：优先使用 JavaScript、TypeScript。
   - AI / 机器学习 / 数据处理：优先使用 Python。
   - 并发、网络服务、系统工具：优先使用 Go、Java、C++ 或 Python。
4. 如果学习者画像显示基础较弱，优先选择语法简单、反馈直接的语言，例如 Python。
5. 如果学习者目标是考试或竞赛，优先选择考试常用语言，例如 C++、Java 或 Python。
6. 如果学习者目标是工程实践，优先选择真实项目中常见的语言，例如 Java、Go、TypeScript 或 Python。
7. 不要同时生成过多语言版本。默认最多生成 1 种语言；只有在多语言对比确实有教学价值时，才生成 2 种语言。

## 生成目标

请围绕课程主题和目标知识点，生成一个完整的代码实操案例。

该案例应采用“分段讲解 + 最终完整代码”的形式：

1. 先说明为什么选择当前编程语言。
2. 再拆分代码实现步骤。
3. 每一步先解释要做什么。
4. 再给出该步骤对应的代码块。
5. 然后解释这段代码的作用。
6. 最后整合出一份完整可运行代码。

代码示例应帮助学习者：
1. 理解知识点在代码中的具体体现
2. 掌握从零到完整实现的过程
3. 看懂每一部分代码的作用
4. 能够复制最终完整代码并直接运行
5. 能够根据案例进行修改和扩展

## 代码要求

1. 代码必须完整可运行
   - 最终完整代码必须包含必要的导入语句。
   - 最终完整代码必须包含完整的主函数或入口逻辑。
   - Python 示例应包含 if __name__ == "__main__":。
   - C/C++ 示例应包含 main 函数。
   - Java 示例应包含完整类定义和 main 方法。
   - Go 示例应包含 package main 和 func main()。
   - JavaScript / TypeScript 示例应说明是在 Node.js 还是浏览器环境运行。
   - Rust 示例应包含 fn main()。
   - C# 示例应包含 Program 入口。
   - SQL 示例应包含可执行的建表、插入或查询语句，并说明数据库环境。

2. 分段代码必须服务于最终完整代码
   - 分段代码应按照实现顺序逐步展开。
   - 每个分段代码块只展示当前步骤相关内容。
   - 分段代码可以不是单独完整程序，但必须能在最终完整代码中找到对应部分。
   - 不要出现分段代码和最终完整代码逻辑不一致的情况。
   - 不要在分段讲解中引入最终代码没有使用的变量、函数或类。

3. 代码必须适合教学
   - 代码不要过度复杂。
   - 变量名、函数名、类名应清晰。
   - 逻辑应直观。
   - 注释应解释关键步骤，而不是机械地每行注释。
   - 示例应突出目标知识点对应的内容。

4. 代码必须与主题相关
   - 不要生成与课程主题和目标知识点无关的代码。
   - 不要为了展示代码而引入不必要的第三方库。
   - 优先使用标准库。
   - 如果确实需要第三方库，必须在运行说明中写清楚安装方式。

5. 讲解必须完整
   - 说明代码实现了什么功能。
   - 说明为什么选择当前语言。
   - 说明核心设计思路。
   - 说明每个分段代码块的作用。
   - 说明关键变量、函数或类的作用。
   - 说明程序运行流程。
   - 说明学习者应重点观察什么。

6. 结合学习者画像
   - 根据学习者画像调整代码复杂度和讲解深度。
   - 如果学习者基础较弱，应拆分得更细，代码更短，解释更清楚。
   - 如果学习者已有一定基础，可以加入更接近真实场景的案例。
   - 如果学习者偏向考试，应突出算法步骤、边界情况和复杂度。
   - 如果学习者偏向项目实践，应突出工程结构、输入输出和可扩展性。
