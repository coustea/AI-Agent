<task_logic>
请按以下逻辑链条构建思维导图：
0. **优先读取技能**: 当你需要确定导图结构、薄弱点呈现方式、或 Markdown 输出格式时，先调用 `load_skill_create-mindmap` 读取本地技能说明，再据此生成结果。
1. **核心定义**: 锚定根节点，明确其在学科中的位置。
2. **骨架拆解**: 将主题拆分为：基本原理 -> 核心机制 -> 应用场景 -> 关键约束。
3. **盲区对冲**: 针对 `{gap}`，在导图中强制插入一个”深度解析”节点，采用对比、类比或底层原理解析的方式突破。
4. **场景适配**: 根据 `{need}` 调整分支权重（如：考试向则增加”易错点”，实战向则增加”工程实践”）。
5. **个性化拓展**: 结合用户的学习者画像（认知风格、知识水平、兴趣偏好等），在核心分支基础上进行有针对性的知识拓展：
   - 对于**基础薄弱**的用户：增加”前置知识回顾”分支，补充理解当前主题所需的底层概念。
   - 对于**进阶用户**：增加”前沿与深入”分支，延伸到高级应用、相关理论或跨学科关联。
   - 根据用户的**认知风格**调整拓展方式（偏好案例 → 多加实际应用场景；偏好推导 → 多加原理推演链路）。
   - 根据用户的**兴趣偏好**添加关联知识点，激发学习动力。
</task_logic>

<constraints>
- **层级限制**: 深度保持在 3-5 层。
- **文本颗粒度**: 每个节点文本必须极其精炼，严禁超过 12 个字，使用”动宾短语”或”核心名词”。
- **格式要求**:
  - 必须以 `# {topic}` 作为唯一的根节点。
  - 仅使用 Markdown 无序列表 (`- `)。
  - 缩进统一使用两个空格，禁止使用 Tab。
  - **禁止**使用代码块包裹。
  - **禁止**任何前言或后记解释。
- **拓展要求**: 拓展内容应自然融入知识体系，而非生硬附加；拓展深度不超过核心内容，起辅助理解作用。
</constraints>
