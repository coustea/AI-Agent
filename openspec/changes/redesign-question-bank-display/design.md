## Context

目前，系统的题库中心（`QuestionBank.vue`）采用单一的、低表现力的扁平 Tab 切换模式。所有的子版块（每日练习、智能练习、检索、模拟组卷、错题本）都在同级直接展示，页面头部只有简易的数据卡片。这种布局缺乏视觉冲击力，且不能体现用户的学习统计特征与刷题行为习惯。

用户已批准“方案 A：流光玻璃态控制中心”设计。我们需要在零后端接口修改的前提下，使用 Vue 3、CSS 动效和 SVG 纯手工绘制重构整个题库页面的展示与交互。

## Goals / Non-Goals

**Goals:**
- 重构题库主视图，实现包含大字正确率 SVG 渐变进度圆环、SVG 动态学习行为雷达图的磨砂玻璃综合仪表盘。
- 实现 5 个高颜值的毛玻璃悬浮卡片入口网格，带位移 hover、霓虹外发光和动态呼吸徽章。
- 为 5 大模块实现沉浸式子工作区，顶部统一固定带有平滑弹性后退动效的毛玻璃面包屑返回条。
- 重构模拟组卷的“考试模式”为 fullscreen 沉浸禅定页面，实现红绿圆钮答题卡。
- 确保整个重构完全在前端（Vue 3 SFCs + Tailwind/Vanilla CSS）内实现，零后端 API 修改。

**Non-Goals:**
- 修改 FastAPI 后端接口。
- 增加或修改 PostgreSQL 数据库表或 Schema。
- 在后端计算雷达图指标，或在后端添加新的错题统计逻辑。
- 改变 subjective 阅卷的 AI 提问与判定流程。

## Decisions

### 1. 纯前端动态雷达指标计算与绑定
- **决策**：雷达图的 5 个指标点（练习量、准确度、错题消灭率、每日坚持度、模考应试力）完全由前端在 bootstrap 之后，从已加载的练习池数据、错题数据和 localStorage 内实时计算。
- **合理性**：用户在错题本中消灭错题（归档或移出）时，雷达图的“错题消灭率”会实时扩充，给用户即时的学习反馈，且不需要后端支持。
- **备选方案**：后端新建统计表，在每次做题提交时更新（成本太高，不符合轻量级重构原则）。

### 2. 纯 SVG 手绘雷达图与动画
- **决策**：不引入 ECharts 或 Chart.js 等重型图表库，使用内联 SVG `<polygon>` 与 `<line>` 手工绘制多边形雷达网和数据区域。
- **合理性**：SVG 元素可以通过 Vue 属性绑定（如 `:points`）无缝联动，能够轻易添加紫色渐变（`linearGradient`）和发光滤镜（`filter`），且对加载性能零损耗。
- **备选方案**：引入 Chart.js 并通过 Canvas 渲染（样式定制困难，发光边框和毛玻璃背景难以实现，且体积庞大）。

### 3. 基于 `viewMode` 的页面跳转与面包屑返回
- **决策**：使用 Vue 3 SFC 内部的 `activeModule` 状态切换和 `<transition name="fade-scale">` 实现子模块的淡入淡出，不在全局路由配置（`routes.ts`）中增加新子路由。
- **合理性**：题库原本就是作为 SPA 内的一个独立功能点，在组件内用状态控制更加紧凑，同时能极易地在面包屑中共享父组件的 `stats` 等数据。
- **备选方案**：将 5 个模块拆分为 5 个独立路由页面（管理分散，数据在页面间传递需要引入 Pinia 或持久化存储，增加了不必要的复杂度）。

## Risks / Trade-offs

- **[Risk] 毛玻璃滤镜的性能与兼容性** → 某些旧款设备或浏览器对 `backdrop-filter` 渲染可能有卡顿，或不支持。
  - *Mitigation*：在 CSS 中设定 `background: rgba(255, 255, 255, 0.72)` 作为备用背景色，即便在滤镜失效时也具有良好的排版可读性。
- **[Risk] 雷达图加载时的坐标闪烁** → 当雷达数据为 0 或未计算出来时，多边形可能渲染为空白或报错。
  - *Mitigation*：在初始化时设定各指标点默认基准值（如 50 分），在数据拉取成功后触发渐变动画至真实坐标点。
