## Context

The backend `videoAgent` produces structured JSON plans describing a computer science tutorial video. To turn this static JSON into actual MP4 videos or visual cards, we require a programmatic rendering system. Motion Canvas is chosen as it allows declaring animations as programmatic generators (TypeScript) and coordinates timelines deterministically. This design doc describes how to construct the standalone `video-render-service` project structure, template registration, theme system, reusable visual blocks, and rendering configurations.

## Goals / Non-Goals

**Goals:**
- **Strict Template Registry**: All templates must register metadata and schemas to prevent runtime execution of arbitrary dynamically generated code.
- **Unified Visual Styling**: Light, readable background (`#F8FAFC`) with card layouts, sufficient padding, and light-theme code blocks.
- **CS educational templates**: 12 specific templates representing data structures, operating systems scheduling, sequence flows, and code walkthroughs.
- **Modular Components**: Build components like CodeBlock (line highlighting), Arrow, NodeBox, MetricTable, TimelineBar.
- **Render Mode Constraints**: Automatically cap video duration, node counts, and steps based on the `video_config.mode` (`quick`, `standard`, `detailed`) to manage rendering time.

**Non-Goals:**
- **Dynamic Code Execution**: No executing of LLM-generated JavaScript/Python directly.
- **Backend Orchestration**: The renderer only reads the static JSON and exports a video file; it does not contain AI logic.
- **Media Hosting/DB persistence**: Saving files to S3/Postgres is handled by the calling service.
- **Overly Complex Animations**: No complex 3D animations, particle physics, or heavy pixel-shaders.

## Decisions

### Decision 1: Registry-based Architecture (TemplateRegistry & TemplateRouter)
- **Choice**: Compile scenes through a strict router that maps `scene.template` to predefined TSX/JSX scene components.
- **Alternatives Considered**: Direct code evaluation (e.g., using `eval` or dynamic JS file loading generated by LLM).
- **Rationale**: Direct code evaluation creates massive security risks (remote code execution) and lacks typing/validation safety. A static registry maps backend schemas reliably.

### Decision 2: Unified Light Theme Palette
- **Choice**: Default main background to `#F8FAFC`, code blocks to `#F1F5F9`, main text to `#1E293B`, and accent color to `#2563EB`.
- **Alternatives Considered**: Classic dark theme or cyberpunk style.
- **Rationale**: Light backgrounds are far easier to read in educational settings, especially for dense code walkthroughs and diagrams.

### Decision 3: Decoupled Render Modes
- **Choice**: Expose `quick`, `standard`, and `detailed` configurations inside components that dynamically trim node counts or transition animations.
- **Alternatives Considered**: Single rendering complexity.
- **Rationale**: Headless rendering on a CPU server can be slow. `quick` mode enables rapid 720p draft renders (useful for immediate preview or fast iterations).

### Decision 4: Modular CS Canvas Components
- **Choice**: Write native Motion Canvas components (e.g. NodeBox using `<Rect>`, Arrow using `<Path>`, etc.) with reactive properties.
- **Alternatives Considered**: Rerendering HTML overlays or SVG objects directly.
- **Rationale**: Motion Canvas `<Rect>` and `<Txt>` nodes are highly optimized for canvas rendering and support layout flexbox matching out-of-the-box.

## Risks / Trade-offs

- **[Risk] Headless Server GPU Acceleration**
  - *Description*: Rendering Motion Canvas via CLI require Chrome/Puppeteer, which might perform slowly on CPU-only servers.
  - *Mitigation*: Enable `quick` mode as default draft output (720p, minimal steps) and configure Puppeteer/Chromium parameters inside `package.json` / `vite.config.ts` to utilize software WebGL rendering (`--use-gl=swiftshader`).

- **[Risk] Schema Drift**
  - *Description*: Backend VideoAgent changes the payload JSON schema.
  - *Mitigation*: Standardize the schema inside a shared TypeScript definition in `schema/videoPlan.ts` and validate incoming payloads using Zod or simple type assertions at startup.
