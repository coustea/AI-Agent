## Why

现有学习路径模块把路径展示、节点学习、资源生成、测验提交和学习评估揉在一起，用户进入路径后看到的更像“资源状态面板”而不是一条可推进的学习路线。随着路径历史、节点主教程、节点测验、专项巩固和强化教程这些能力被明确下来，旧的数据模型和后端服务边界已经无法稳定承载新的学习闭环。

现在需要把学习路径重构成一个独立的教学流程系统：先生成路径，再进入节点学习，再通过节点测验决定推进、巩固或强化，同时把路径历史、节点教程、路径专属题目和节点辅助资源完整落库，支撑用户后续复习和恢复学习。

## What Changes

- **BREAKING** 重建学习路径域的数据模型，废弃现有基于 `course_paths`、`course_path_nodes`、`course_path_resource_bindings` 的路径业务主链路，改为围绕 `learning_paths`、`path_nodes`、`path_node_tutorials`、`path_node_questions`、`path_node_resources` 组织新系统。
- 新增“路径需求输入页 -> 路径总览页 -> 节点学习页”的三段式学习流程，明确把路径展示与节点学习拆分。
- 新增路径历史能力，允许用户拥有多条路径，并从历史记录中继续学习旧路径。
- 新增节点教程版本体系，支持主教程、专项巩固教程和强化版教程，并保留强化教程与原教程的派生关系。
- 新增路径专属题目体系，使用独立题目表存储 AI 在线生成的节点测验题，支持多轮 5 道选择题测验、用户作答、判分和错题知识点提取。
- 新增节点辅助资源体系，独立存储思维导图、PPT、代码示例等按需生成的额外资源。
- 重写学习路径后端 API 和服务边界，路径规划域不再复用旧的资源绑定式接口作为主业务流程。

## Capabilities

### New Capabilities
- `learning-path-management`: 管理学习路径的创建、当前路径读取、历史路径查询和继续学习。
- `path-node-learning`: 管理节点教程、节点测验、巩固教程、强化教程和节点推进状态。
- `path-node-resources`: 管理节点下按需生成的思维导图、PPT、代码示例等辅助资源。

### Modified Capabilities
- `tutor-profile-update`: 学习路径重构后，路径学习事件与学习结果仍需继续向画像更新链路提供有效信号，但信号来源将从旧路径事件结构迁移到新路径域的节点学习结果。

## Impact

- 后端数据库模型、初始化 schema 和路径相关接口将发生 breaking change。
- 现有 `server/app/path/` 模块需要重写或被新的学习路径模块替代。
- 前端 `src/learning/` 下的路径总览、节点学习、路径历史页面和相关 API 调用需要重构。
- 旧路径数据不再兼容；开发环境和测试数据需要基于新表结构重新初始化。
