## Context

当前学习路径模块以“路径节点绑定资源”的思路建模：路径主表负责总览，节点表负责解锁状态，节点资源通过绑定表关联到通用资源生成结果。这一模型适合“节点生成一份资源然后继续查看”的简单流程，但无法自然表达新的学习闭环：节点主教程、用户手动触发的辅助资源、节点专属测验、第一次不过后的专项巩固、第二次不过后的强化版教程，以及两次未通过后以 `completed_with_gaps` 状态继续推进。

本次重构明确不需要兼容旧路径代码和旧路径数据，允许直接替换学习路径域的后端主模型、API 和服务边界。用户已经确认新的产品结构应当拆成路径需求输入页、路径总览页和节点学习页三个页面，后端需要优先为这一新流程建立稳定的数据模型和接口。

## Goals / Non-Goals

**Goals:**
- 建立新的学习路径数据模型，覆盖路径、节点、教程、题目和节点辅助资源。
- 让学习路径成为独立域，不再依赖旧的 `generated_resources` 绑定链路承载节点教程和路径题目。
- 支持“一条路径多节点、多轮教程、多轮题目”的节点学习闭环。
- 支持多条路径历史，并保证默认读取用户当前最新路径。
- 为后续前端三页面重构提供稳定、清晰的后端 API。

**Non-Goals:**
- 不兼容旧路径数据库结构和旧路径接口返回格式。
- 不在本次重构中设计完整错题本模块，只保留支撑节点专项巩固所需的错题知识点信息。
- 不复用公共题库 `quiz_questions` 作为路径节点测验主数据源，路径测验题由 AI 在线生成并存入专用表。
- 不把路径节点的教程、题目和辅助资源继续映射回旧的通用资源历史页。

## Decisions

### 1. 以学习路径专属表为核心重建路径域
- **Decision:** 新建 `learning_paths`、`path_nodes`、`path_node_tutorials`、`path_node_questions`、`path_node_resources` 五张主表作为学习路径域的核心模型。
- **Why:** 新的业务规则本质上是“路径 -> 节点 -> 教程/题目/辅助资源”的教学流程，而不是“节点 -> 绑定一份通用资源”。直接重建表结构比继续在旧模型上缝补更清晰，也更符合“不需要兼容旧代码”的约束。
- **Alternatives considered:**
  - 继续沿用 `course_paths` / `course_path_nodes`：会把新流程继续塞进旧状态机，难以区分节点结构状态和节点学习状态。
  - 只新增局部字段：短期省事，但后端服务职责仍然会缠在一起。

### 2. 节点教程、节点题目和节点辅助资源彻底脱离旧通用资源主链路
- **Decision:** `path_node_tutorials` 存储主教程、专项巩固教程和强化版教程；`path_node_questions` 存储节点专属 5 道选择题及用户作答；`path_node_resources` 存储导图、PPT、代码示例等额外资源。
- **Why:** 路径学习内容必须可复习、可回看、可按节点恢复，而路径节点教程与路径节点题目都属于场景化、节点化数据，不适合作为通用资源生成记录继续存在。
- **Alternatives considered:**
  - 教程复用 `generated_resources`，题目单独建表：会导致路径域仍依赖旧资源模块，无法真正独立。
  - 所有节点内容塞进一张大表：会让教程、题目和资源这些异构内容混在一起，后续查询和状态维护都会变脏。

### 3. 路径节点测验使用单表承载题目与作答快照
- **Decision:** `path_node_questions` 每一行表示某节点某一轮生成的一道题，直接持有 `question`、`choice`、`answer`、`response`、`analysis` 等字段，并补充 `path_id`、`node_id`、`tutorial_id`、`round_no`、`question_no`、`mode`、`is_correct` 等上下文字段。
- **Why:** 用户已经确认路径规划题目需要单独表存储 AI 在线生成内容，并且最基本字段必须包含题干、选项、标准答案、用户回答和解析。由于路径节点测验固定为 5 道选择题，按轮次新增新行即可，不需要为第一版额外拆分测验定义表和作答表。
- **Alternatives considered:**
  - 复用 `quiz_questions`：与“路径题目是专属在线生成题”这一决策冲突。
  - 题目定义表 + 作答表二拆：更标准，但第一版相对更重，不符合“先把大方向做出来”的节奏。

### 4. 节点学习流程使用教程轮次和节点状态共同驱动
- **Decision:** `path_nodes.status` 只表达路径推进语义：`locked`、`available`、`completed`、`completed_with_gaps`。教程和题目轮次通过 `path_node_tutorials.type`、`path_node_questions.mode`、`attempt_count` 共同表达。
- **Why:** 用户当前更关心能否推进到下一个节点，以及某节点是否在学习后仍存在掌握缺口；页面内“正在看主教程 / 巩固教程 / 强化版教程”的切换可以由教程类型和当前教程指针来表达，不需要把所有瞬时学习态都塞进节点状态列。
- **Alternatives considered:**
  - 设计更复杂的节点运行状态机表：更完整，但会拉高第一版实现复杂度。
  - 只靠事件表判断轮次：业务真相会分散在日志里，不利于路径恢复与复习。

### 5. 默认进入最新路径总览，历史页单独承担多路径管理
- **Decision:** 当前路径读取接口返回用户最新的 active 路径；历史页单独查询 archived / completed 路径，并支持继续学习旧路径。
- **Why:** 用户已经确认日常进入路径规划时应直接看到最新路径总览，但需要一个历史记录页管理旧路径，旧路径继续学习应视为续档而不是重开。
- **Alternatives considered:**
  - 每次进入路径规划都先让用户选择路径：主流程噪音太大。
  - 历史路径只允许查看：无法满足“以前的路径可以继续学习”的目标。

## Risks / Trade-offs

- **[Risk] 全量替换路径域后，旧前端页面和旧测试会大面积失效** → **Mitigation:** 先完成新表、新 API 和新服务骨架，再分阶段切前端页面和测试，最后删除旧路径实现。
- **[Risk] `path_node_questions` 同表承载题目定义与用户回答，后续扩展复杂测验时可能不够灵活** → **Mitigation:** 第一版先以固定 5 道单选题闭环为准，保留 `round_no`、`mode`、`question_no`、`submitted_at` 等字段，为后续拆表预留升级路径。
- **[Risk] 路径教程完全脱离旧通用资源模块后，会出现一套新的内容生成链路** → **Mitigation:** 保留底层 AI 生成能力复用，但路径域自行定义 tutorial/resource 持久化模型和 API。
- **[Risk] 路径历史和当前 active 路径切换若只靠应用逻辑，容易出现多个 active 路径** → **Mitigation:** 在数据库层加入“同一用户仅一条 active 路径”的约束，并在服务层统一处理激活与归档。

## Migration Plan

1. 新增学习路径专属表与对应 ORM 模型。
2. 在新模块中实现路径创建、当前路径查询、路径历史、节点学习、题目提交和节点资源生成 API。
3. 用新 API 接管前端路径输入页、路径总览页、节点学习页和路径历史页。
4. 删除旧 `server/app/path/` 中不再使用的接口和服务逻辑。
5. 删除旧路径相关的前端 API、页面状态和兼容代码。
6. 重新初始化开发环境数据库和测试数据。

## Open Questions

- `learning_paths` 是否需要单独保留阶段表，还是先将阶段信息放入 `path_nodes.stage` 字段并由前端按阶段聚合。当前实现方案优先用 `path_nodes.stage` 简化第一版。
- `path_node_resources.content` 是否统一使用 JSONB，还是根据资源类型拆成 `content_text` / `content_json`。当前实现方案优先使用 JSONB，减少异构字段数量。
