# 课件制作

用 `generate_presentation` 工具生成真实的 .pptx 文件。
工具返回 `artifact_id`，生成在后台进行，完成后可下载。

## 制作流程

### 1. 先规划大纲，再调用工具

不要跳过规划直接堆页数。一份合格的课件有清晰的叙事线：

- **封面**：主题 + 一句话定位
- **引入**：为什么学这个、解决什么问题
- **主体**：按概念依赖顺序展开，每页一个知识点
- **总结**：要点回顾 + 下一步建议

页数建议 5-12 页。学生明确要求页数时按学生的来。

### 2. 每页只讲一个知识点

| 该做 | 不该做 |
| --- | --- |
| 标题是名词短语，如「Channel 的两种形态」 | 标题是长句，如「我们来看看 Channel 有哪两种形态」 |
| 3-5 条要点，每条一句话 | 一整段文字塞进一页 |
| 要点之间是并列或递进关系 | 要点之间逻辑跳跃 |
| 单条要点不超过 40 字 | 单条要点写成一整段 |

**硬限制**：单页最多 6 条要点，单条最多 160 字，超出工具会拒绝。
被拒绝时按提示拆分页面，不要硬塞。

### 3. 需要图示时先画图

如果某页需要结构图或流程图，先调用 `generate_diagram` 生成图解，
再在课件该页的要点里描述它，并告知学生图解已单独生成。
课件本身不支持内嵌图片。

## 参数示例

```json
{
  "title": "Go 并发模型入门",
  "subtitle": "从 goroutine 到 GMP 调度",
  "slides": [
    {
      "title": "为什么需要并发",
      "bullets": [
        "单核性能提升已接近物理极限",
        "多核并行是唯一可扩展的方向",
        "并发模型决定了代码的复杂度上限"
      ]
    },
    {
      "title": "Goroutine 是什么",
      "bullets": [
        "由 Go 运行时调度的用户态执行单元",
        "初始栈仅 2KB，可按需增长",
        "创建十万个也不会耗尽内存",
        "与线程的关键区别：M:N 调度"
      ],
      "note": "强调它不是线程，避免学生套用线程池的思维"
    }
  ]
}
```

## 生成之后

- 如实告知当前状态：`queued` / `running` / `completed`。
- 生成中不要谎称「已经好了」。学生追问进度时用 `get_artifact_status` 查询。
- 完成后给出下载链接与页数。
- 如果学生要修改，重新调用工具生成新课件，不要让学生手动改。
