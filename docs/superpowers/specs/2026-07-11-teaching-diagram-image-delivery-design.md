# 教学图解图片化与可靠交付设计

## 目标

将聊天中的教学图解改为可查看、下载的 A 风格知识信息图 PNG，并保证图片渲染异常时仍向用户交付可用图解。

## 范围

- 图解由现有结构化 JSON 驱动，图片由后端渲染。
- 主视觉采用用户确认的 A 风格：标题、分栏/分区知识区、关系说明和结论区。
- 流程、层级等内容保留各自语义，但使用同一套配色、边框、标题和结论视觉体系。
- 失败时自动重试一次；仍失败时回退到结构化图解，而非静默省略。

## 不在范围内

- 不调用外部 AI 绘图服务。
- 不改变独立 resource 或 learning-path 的模型、持久化和详情页。
- 不修改图解生成的 LLM 结构化 JSON 协议，除为失败回退增加可选状态字段外。

## 架构与数据流

1. Tutor Agent 继续生成并校验 `StructuredTeachingDiagram`。
2. Chat service 调用图片渲染器。渲染器将图解类型映射为 A 风格 HTML，并截图为 PNG。
3. 渲染成功时，SSE `diagram.ready` 返回 `TeachingDiagramImage`，包含图片 URL、尺寸、类型和标题。
4. 截图失败时，渲染器记录原因并重启浏览器后自动重试一次。
5. 第二次失败时，Chat service 发送一个包含原 `StructuredTeachingDiagram` 的回退 payload，并明确标记图片未生成；不得将 `diagram_result` 改为 `None` 或跳过事件。
6. 前端根据 payload 类型展示 PNG 或结构化回退图解。两种形态均能打开详情；PNG 形态支持下载，回退形态显示“重新生成图片”操作。

## 服务端设计

### 图片模板

渲染器从 `graph_type` 选择布局策略：

- `comparison`：左右实体对照、中心承载关系、底部维度对比。
- `flowchart`、`sequence`、`timeline`：顺序节点与箭头、关键说明、底部结论。
- `framework`、`hierarchy`、`tree`：中心主题与分支卡片、关键知识总结。
- `grid`、`protocol`、`summary`：分区表格/卡片、重点字段或知识结论。

所有图片使用中文固定标签和内容，删除面向开发者的英文徽标。输出尺寸根据实际内容高度自适应，并限制单个区块、列表和文本的最大数量，防止无限高度或截图失败。

### 可靠性

- 将 Playwright 浏览器管理与单次截图分离，保证截图超时、浏览器关闭和异常后能够创建干净实例。
- 每次渲染最多尝试两次；重试前记录第一次异常并清理失效浏览器资源。
- 记录会话、图解类型、尝试次数、失败阶段和异常摘要，便于排查浏览器安装、启动和截图问题。
- 若两次均失败，返回结构化回退 payload，并包含可供前端显示的失败状态；不再只写警告日志后丢弃图解。

## 前端设计

- `TeachingDiagramImage` 继续负责 PNG 缩略图、放大预览和下载。
- 结构化图解组件继续作为回退渲染器，并应用 A 风格外层、标题与结论区域，使图片与网页回退视觉一致。
- 消息状态区分“正在生成”“图片生成失败，已展示图解”“已生成图片”。
- “重新生成图片”仅对当前消息发起请求；成功后原地替换为 PNG，失败后保留结构化图解和可读提示。

## 错误处理

| 场景 | 服务端行为 | 前端行为 |
| --- | --- | --- |
| 首次截图失败 | 记录异常，自动重试一次 | 继续显示生成中 |
| 第二次截图失败 | 发送结构化回退 payload | 展示图解及失败提示、重新生成按钮 |
| SSE/网络中断 | 不伪造图片成功状态 | 结束加载并显示可重试错误 |
| 回退图解无效 | 发送明确错误状态 | 显示简短说明与重试按钮 |

## 测试策略

- 后端：首轮异常后二轮成功；两轮异常仍返回保留原图解的回退 payload；模板输出包含 A 风格的关键布局和中文标签；异常记录包含尝试信息。
- 前端：PNG、回退、失败三种状态的消息渲染；回退状态可触发重新生成；重试成功后替换为图片。
- 集成验证：使用真实 Playwright Chromium 生成一张 PNG，验证响应图片可访问及历史消息可重新显示。

## 验收标准

- 用户选择图解后，成功路径得到可放大和下载的 A 风格 PNG。
- 任一单次 Playwright 截图失败不会导致图解缺失。
- 连续两次截图失败仍能看到信息完整的网页图解，并能手动重试图片。
- 页面不再出现“图解生成结束但没有任何内容或原因”的状态。
